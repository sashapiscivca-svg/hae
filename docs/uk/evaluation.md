# Оцінювання

[English](../en/evaluation.md) · [Зміст документації](README.md)

## Протокол, за яким отримано опубліковані результати

- **Набори:** `hituav_test` (офіційна тестова підмножина HIT-UAV), `airesq_val` (групи записів AIResQ, відкладені повністю) і `wisard_ir_val` (тепловізійна частина WiSARD, три відкладені локації, які ніколи не використовувалися ні для навчання, ні для жодного вибору). Анотації містяться в `data/annotations/`.
- **Вхід:** int8-модель ONNX (fp32 наведено поруч) на повних кадрах 640×512, збільшених у 1,5 раза, без розбиття на тайли й без аугментації під час тестування.
- **Зіставлення:** жадібне зіставлення виявлень, відсортованих за оцінкою, з еталонною розміткою без урахування класу при IoU ≥ 0,5. Виявлення, що потрапляють в ігноровану область (категорія 3), не вважаються ні істинно, ні хибно позитивними.
- **AP50:** площа під інтерпольованою кривою точність–повнота (precision–recall) у стилі COCO при IoU 0,5 для класу `person`.
- **Метрики оператора** за порога впевненості: повнота (recall), точність (precision), F1 і кількість хибних тривог на кадр. Два пресети моделі беруться з метаданих ONNX: `balanced` (максимум середнього F1) і `sensitive` (максимум середнього F2); обидва обрано на HIT-UAV test і AIResQ val.
- **Один запуск.** Кожен опублікований результат отримано в одному запуску навчання. Для подібних рецептів повторні запуски відрізнялися приблизно на 0,02 AP50 на HIT-UAV і на 0,04–0,08 на AIResQ.

## Запуск

```bash
python scripts/evaluate.py --model models/hae-s-ir/hae-s-ir_lwir_int8.onnx --data data --sets hituav_test,airesq_val,wisard_ir_val
python scripts/evaluate.py --model models/hae-s-ir/hae-s-ir_lwir_int8.onnx --data data --sets airesq_val --conf 0.3,0.4,0.5 --json airesq.json
python scripts/evaluate.py --model models/hae-s-ir/hae-s-ir_lwir.onnx --data data --sets wisard_ir_val --scale 1.0
```

Скрипт виводить AP50 і метрики оператора для кожного набору, а з `--json` зберігає повний звіт. `--every k` оцінює кожен k-й кадр для швидкої перевірки. Результати, які він видає для опублікованої моделі, мають збігатися з `models/hae-s-ir/metrics.json`.

## Оцінювання на власних зйомках

Це найважливіший крок перед операцією. Розмітьте у форматі COCO кількасот кадрів, яких модель ніколи не бачила, з **вашої** камери на **ваших** висотах (див. [data.md](data.md#використання-власних-даних)), а потім запустіть на них `scripts/evaluate.py`. Зверніть увагу на:

1. **повноту за порога, який ви плануєте використовувати**: яку частку людей буде показано операторові?
2. **хибні тривоги на кадр**: помножте їх на кількість кадрів, які детектор обробляє за хвилину, щоб отримати навантаження тривогами на оператора за хвилину. Підтвердження в часі (трекінг) суттєво зменшує це навантаження.
3. **перебір `--scale`** (наприклад, 1,0 / 1,25 / 1,5): він може важити більше за поріг, коли люди на ваших кадрах більші або менші, ніж у навчальних даних.

## Чому AP50 недооцінює якість на крихітних людях

Для людини розміром 6 пікселів рамка, зміщена на 2 пікселі, уже має IoU нижче 0,5 і зараховується як пропуск *і* хибна тривога, хоча оператор побачив би правильне місце. Тому `hae.recall.recall_center` надає зіставлення **на основі центру**: виявлення вважається влучанням, якщо його центр лежить усередині рамки людини, розширеної на 2 пкс, а виявлення, розташовані ближче ніж 8 пкс одне від одного, рахуються як одна тривога. Таке зіставлення ближче до того, що відчуває рятувальник. Основні опубліковані результати використовують стандартний протокол IoU, щоб їх можна було порівнювати з літературою.
