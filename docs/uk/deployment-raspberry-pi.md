# Розгортання на Raspberry Pi Zero 2 W

[English](../en/deployment-raspberry-pi.md) · [Зміст документації](README.md)

Raspberry Pi Zero 2 W (чотири ядра Cortex-A53 на 1 ГГц, 512 МБ RAM, близько 15 $) — найдешевша цільова платформа, для якої розроблено hae. Усі наведені нижче результати **виміряно на самому пристрої**: Zero 2 W Rev 1.0, Raspberry Pi OS Bookworm 64-bit, Python 3.11.2, регулятор частоти `performance`, без радіатора, onnxruntime на CPU. Час — медіана (p50) повторних запусків.

## Встановлення

```bash
sudo apt install -y python3-venv python3-pip
python3 -m venv ~/hae-env && . ~/hae-env/bin/activate
pip install numpy onnxruntime opencv-python-headless pillow onnx
pip install --no-deps "hae @ git+https://github.com/sashapiscivca-svg/hae"      # лише середовище виконання, без PyTorch
# скопіюйте models/hae-s-ir/hae-s-ir_lwir_int8.onnx (383 KB) на Pi
```

Потрібна 64-бітна ОС, оскільки onnxruntime публікує wheel-пакети для aarch64. Пікове споживання пам'яті повним конвеєром «детектор + трекер» становило 175–185 МБ із 416 МБ, доступних ОС.

## Виміряна затримка

| hae-s-ir | 1 потік | 4 потоки |
|---|---:|---:|
| int8, один тайл 256×320 | 148 мс | 55 мс |
| fp32, один тайл 256×320 | 208 мс | 82 мс |
| int8, повний кадр 640×512 при ×1,5 | 1411 мс | 554 мс |

Використовуйте int8-модель: на цьому CPU вона приблизно на 30 % швидша за fp32 за тієї самої точності. Декодування в numpy займає близько 7,5 мс на тайл. На цій платі затримка була приблизно в 16–40 разів вищою, ніж в одному потоці x86-ноутбука, тож не екстраполюйте з вимірювань на настільних комп'ютерах.

Відтворити вимірювання можна так:

```bash
python scripts/bench.py models/hae-s-ir/hae-s-ir_lwir_int8.onnx --threads 1
python scripts/bench.py models/hae-s-ir/hae-s-ir_lwir_int8.onnx --threads 4
```

## Температура та живлення

Без радіатора за безперервного навантаження всіх чотирьох ядер плата за 5 хвилин нагрілася до **81,7 °C**, а тактова частота знизилася до 834 МГц. За 1–3 завантажених ядер плата трималася на рівні близько 56 °C. Для польотів:

- встановіть радіатор (і, якщо можливо, забезпечте обдув);
- обмежте інференс 3 потоками (`Detector(..., threads=3)`) і залиште одне ядро для захоплення кадрів і телеметрії;
- стежте за `vcgencmd measure_temp` і `vcgencmd get_throttled`.

Енергоспоживання ми не вимірювали.

## Стратегія роботи в реальному часі

Тепловізійна камера видає 9–30 кадрів за секунду, тоді як hae-s-ir потребує близько 0,55 с на повний кадр 640×512 при ×1,5 у чотирьох потоках. Не запускайте детектор на кожному кадрі:

1. Запускайте детектор кожні *K* кадрів (K = 3–8) і обирайте *K* адаптивно, виходячи з бюджету часу, скажімо, 150–200 мс на кадр.
2. Між виявленнями супроводжуйте кожного кандидата дешевим трекером (кореляційним фільтром або оптичним потоком).
3. Сповіщайте оператора лише тоді, коли кандидат зберігається впродовж кількох виявлень. Це також придушує більшість хибних тривог, що з'являються на одному кадрі.

У наших тестах конвеєра на пристрої ця схема працювала зі швидкістю близько 7 кадрів за секунду з тепловізійним детектором розміру `s` (і 6–12 кадрів за секунду з меншим, залежно від *K*).

Інші способи заощадити час:

- **Зменшіть масштаб** (`scale=1.0` або `1.25`), коли летите нижче або коли люди на кадрі більші за приблизно 25 пкс. Витрати зменшуються пропорційно квадрату масштабу.
- **Область інтересу:** запускайте детектор на вирізаній частині кадру (наприклад, нижче від лінії горизонту).

## Мінімальний бортовий цикл

```python
import cv2
from hae.detector import Detector

det = Detector("models/hae-s-ir/hae-s-ir_lwir_int8.onnx", threads=3)   # рекомендовані масштаб і поріг беруться з метаданих
cap = cv2.VideoCapture(0)                                               # тепловізійна камера як пристрій V4L2
k, K = 0, 5
while True:
    ok, frame = cap.read()
    if not ok:
        break
    if k % K == 0:
        gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY) if frame.ndim == 3 else frame
        dets = det.detect(gray)                    # (n, 6): x1, y1, x2, y2, score, class
        for x1, y1, x2, y2, s, _ in dets:
            print(f"candidate {s:.2f} at {(x1 + x2) / 2:.0f},{(y1 + y2) / 2:.0f}")
    k += 1
```

Тепловізійний вхід має бути **8-бітним зображенням у відтінках сірого** з камери (палітра white-hot). Радіометричні 14/16-бітні дані спершу потребують перетворення у 8 біт на кшталт AGC (автоматичного регулювання підсилення). Кольорові палітри (ironbow і подібні) не підтримуються.
