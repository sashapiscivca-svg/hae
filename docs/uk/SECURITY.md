# Повідомлення про проблеми безпеки

[English](../../SECURITY.md)

## Про що повідомляти

- **Вразливості безпеки** в коді, наприклад небезпечна десеріалізація, обхід шляхів (path traversal) у CLI або шкідливі файли моделей, що проходять перевірку цілісності.
- **Проблеми безпеки в моделях**: систематичні режими відмови, які можуть коштувати життів (категорія потерпілих, сенсор чи місцевість, де людей стабільно пропускають), неправильні пресети чи метадані або опубліковані результати, які вам не вдається відтворити.
- **Зловживання** hae, що суперечить [RESPONSIBLE_USE.uk.md](../../RESPONSIBLE_USE.uk.md).

## Як повідомити

Будь ласка, скористайтеся **приватним повідомленням про вразливості GitHub** (GitHub private vulnerability reporting) у цьому репозиторії (вкладка «Security» → «Report a vulnerability»). Так повідомлення приватно надходить до супровідників. Не відкривайте публічний issue для повідомлень про вразливості чи зловживання. Проблеми з якістю моделі, які не є чутливими, можна надсилати звичайними issues на GitHub.

Будь ласка, укажіть версію (`pip show hae`), назву моделі, кроки чи дані для відтворення (достатньо кількох кадрів) і те, чого ви очікували.

Ми прагнемо підтверджувати отримання повідомлень протягом 7 днів і публікувати виправлення або бюлетень безпеки протягом 90 днів. Якщо ви повідомите про проблему безпеки моделі, ми згадаємо вас у журналі змін, якщо ви не заперечуєте.

## Перевірка файлів моделей

Кожен опублікований файл наведено з його SHA-256 у `models/SHA256SUMS`:

```bash
cd models && sha256sum -c SHA256SUMS
```

Завантажуйте моделі лише з цього репозиторію або з його офіційного репозиторію на Hugging Face. Опубліковані формати (ONNX і safetensors) не можуть виконувати код під час завантаження. Контрольні точки навчання (`.pt`) використовують Python pickle, тому передавайте в `hae.checkpoint.load_checkpoint` або `scripts/export.py` лише ті файли `.pt`, які створили самі.
