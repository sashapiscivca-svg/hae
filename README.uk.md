# hae (해) — відкритий тепловізійний детектор людей для пошуково-рятувальних дронів

**Модель на 313 тис. параметрів, яка знаходить людей на тепловізійних знімках із дронів і працює на Raspberry Pi Zero 2 W вартістю 15 $.**

[English](README.md) · [Картка моделі](MODEL_CARD.uk.md) · [Картка даних](DATA_CARD.uk.md) · [Документація](docs/uk/README.md) · [Відповідальне використання](RESPONSIBLE_USE.uk.md)

`код: MIT` · `ваги: MIT` · `v1.0.0` · `Python ≥ 3.10` · `середовище виконання: numpy + onnxruntime (без PyTorch)`

</div>

---

Після повеней, землетрусів і цунамі, а також коли людина заблукала в лісі чи в горах, дрон із тепловізійною камерою обстежує територію значно швидше, ніж піший пошуковий ланцюг. Проте з висоти 50–120 м людина займає лише кілька пікселів, і оператор, який годинами стежить за відео в реальному часі, частину людей пропустить. **hae** (해, корейською «сонце») — невеликий, повністю відкритий нейромережевий детектор, який позначає ймовірних людей на тепловізійних (LWIR) знімках із дронів. Його призначення — допомагати пошуковцям, а не замінювати їх.

Відкрито все: код інференсу та навчання, натреновані ваги (ONNX fp32 / int8 і PyTorch `safetensors`), точний рецепт навчання, протокол оцінювання та анотації кожної підмножини даних. Модель навчено **з нуля** на цивільних наборах даних із відкритими ліцензіями. Жодних сторонніх попередньо натренованих контрольних точок не використано.

> [!IMPORTANT]
> hae — це **дослідницький реліз** та інструмент **підтримки ухвалення рішень**. Він пропускає людей і подає хибні тривоги (див. [Обмеження](#обмеження)). Ніколи не використовуйте його як єдиний засіб пошуку й ніколи не припиняйте пошук через негативний результат. Перед розгортанням прочитайте [RESPONSIBLE_USE.uk.md](RESPONSIBLE_USE.uk.md).

## Модель

| | **hae-s-ir** v1.0.0 |
|---|---|
| Задача | виявлення людей (один клас) на тепловізійних (LWIR, 8-бітних у відтінках сірого) аерокадрах |
| Параметри | 313 169 |
| Обчислення | 0,269 GMAC на тайл 256×320 при ×1,0; рекомендований масштаб входу ×1,5 |
| Файли | `hae-s-ir_lwir_int8.onnx` **383 КБ** (для розгортання) · `hae-s-ir_lwir.onnx` 1,2 МБ (fp32) · `hae-s-ir.safetensors` (PyTorch, для донавчання) |
| Точність (int8) | AP50 **0,757** на HIT-UAV test · 0,230 на AIResQ val · 0,087 на WiSARD-IR (тест на перенесення) |
| Швидкодія | **55 мс** на тайл 256×320 на Raspberry Pi Zero 2 W (4 потоки, виміряно) |
| Навчання | з нуля, 90 епох, HIT-UAV + AIResQ, 42 хв на одній NVIDIA T4 |
| Ліцензія | MIT |

Усе про модель міститься в [`models/hae-s-ir/`](models/hae-s-ir): `config.json` (архітектура та повний рецепт навчання), `metrics.json` (усі результати оцінювання, зокрема перебір порогів) і контрольні суми SHA-256 у [`models/SHA256SUMS`](models/SHA256SUMS).

**Чому лише одна модель?** Ми натренували сімейство розмірів (n/t/s/m) і лінійку RGB-моделей. У цьому релізі — модель, за яку ми можемо поручитися. hae-s-ir найточніша на основному тепловізійному бенчмарку (вона перевершує `m`, яка більша в 2,6 раза) і вкладається в обчислювальний бюджет Raspberry Pi Zero 2 W. RGB-лінійка ще не готова до релізу. Інші варіанти з'являться лише тоді, коли вони даватимуть очевидну користь.

## Швидкий старт

```bash
git clone https://github.com/sashapiscivca-svg/hae && cd hae
pip install -e .                                        # лише середовище виконання: numpy, onnxruntime, opencv, onnx, pillow
```

Командний рядок:

```bash
hae info hae-s-ir                                       # метадані: передобробка, масштаб, пороги, ліцензія
hae predict hae-s-ir path/to/thermal_frames/ --json     # результати зберігаються в runs/predict/exp*/
hae predict hae-s-ir frame.png --preset sensitive       # вища повнота, більше хибних тривог
hae predict hae-s-ir big_frame.png --tile 256,320       # розбиття на тайли для кадрів, значно більших за 640×512
```

Python:

```python
from hae.detector import Detector

det = Detector("hae-s-ir")             # масштаб, передобробка й поріг беруться з метаданих ONNX
res = det.predict("frame.png")         # або масив numpy, каталог чи список шляхів
print(res.summary())
for (x1, y1, x2, y2), score in zip(res.boxes, res.conf):
    print(f"person {score:.2f} at ({x1:.0f},{y1:.0f})-({x2:.0f},{y2:.0f})")
res.save("frame_detections.png")
```

Без клонування репозиторію команди `pip install "hae[hub] @ git+https://github.com/sashapiscivca-svg/hae"` та `hae download hae-s-ir` завантажують ваги з [Hugging Face Hub](https://huggingface.co/sashapiscivca-svg/hae-s-ir). Файли можна запускати безпосередньо в будь-якому середовищі виконання ONNX (C++, Rust, мобільні платформи, вебзастосунки). Контракт входів і виходів описано в [docs/uk/inference.md](docs/uk/inference.md).

## Результати

Модель навчено один раз (seed 0). Повторний запуск рецепта змінює AP50 приблизно на ±0,02 на HIT-UAV і на ±0,04–0,08 на менших наборах. Зіставлення виконується за IoU ≥ 0,5 без урахування класу. «FP/кадр» — кількість хибних тривог на кадр. Протокол описано в [docs/uk/evaluation.md](docs/uk/evaluation.md).

| Набір для оцінювання | Кадри | Люди | AP50 fp32 | AP50 int8 | Збалансований пресет (0,50): повнота (recall) / точність (precision) / FP на кадр | Чутливий пресет (0,45): recall / precision / FP на кадр |
|---|---:|---:|---:|---:|---|---|
| HIT-UAV test (у межах домену) | 579 | 2 611 | 0,758 | **0,757** | 0,73 / 0,75 / 1,09 | 0,77 / 0,70 / 1,50 |
| AIResQ val (у межах домену, реальні рятувальні зйомки, люди ~8 пкс) | 502 | 933 | 0,238 | 0,230 | 0,52 / 0,24 / 3,11 | 0,56 / 0,19 / 4,42 |
| WiSARD-IR val (**перенесення**: модель на ньому ніколи не навчали й не налаштовували) | 1 633 | 2 439 | 0,086 | 0,087 | 0,17 / 0,16 / 1,28 | 0,19 / 0,13 / 1,86 |

Як це читати:

- На зйомках, подібних до HIT-UAV (камери того самого типу, люди заввишки близько 19 пкс), модель знаходить **приблизно три чверті людей за приблизно однієї хибної тривоги на кадр**.
- На AIResQ, де в реальних рятувальних зйомках люди мають висоту близько 8 пкс, вона знаходить приблизно половину з них за приблизно трьох хибних тривог на кадр.
- На WiSARD-IR, отриманому з інших камер і локацій, де люди більші (медіана 32 пкс), модель **здебільшого не справляється**. Це найважливіше застереження щодо цього релізу: тепловізійні детектори ненадійно переносяться між камерами та висотами. Перевіряйте модель на власних зйомках і, якщо можете, донавчайте її.

Для контексту: опубліковані найсучасніші детектори з backbone, попередньо натренованими на ImageNet, і зі в 100–1000 разів більшим обсягом обчислень досягають приблизно 0,50 mAP50 на спорідненому бенчмарку RGBTDronePerson. hae не змагається з ними в точності. Її ціль — апаратне забезпечення, яке має бюджет на модель лише в кількасот кілобайтів і один малопотужний CPU.

## Швидкодія на Raspberry Pi Zero 2 W

Виміряно **на самому пристрої** (Raspberry Pi Zero 2 W Rev 1.0, Raspberry Pi OS Bookworm 64-bit, Python 3.11, onnxruntime, регулятор частоти `performance`, без радіатора). Наведено значення p50.

| hae-s-ir | 1 потік | 4 потоки |
|---|---:|---:|
| int8, один тайл 256×320 | 148 мс | **55 мс** |
| fp32, один тайл 256×320 | 208 мс | 82 мс |
| int8, повний кадр 640×512 при ×1,5 | 1411 мс | 554 мс |

Без радіатора плата за п'ять хвилин роботи на всіх чотирьох ядрах нагрілася до 81,7 °C і почала знижувати частоту, тож у польоті використовуйте радіатор. Для відео в реальному часі запускайте детектор кожні *K* кадрів, супроводжуйте об'єкти трекером між виявленнями та зменшуйте масштаб входу, коли люди на кадрі великі. Подробиці та команда для вимірювання швидкодії (`scripts/bench.py`) — у [docs/uk/deployment-raspberry-pi.md](docs/uk/deployment-raspberry-pi.md).

## Як це працює

```
тепловізійний кадр ─► z-нормалізація кадру ─► збільшення ×1.5 ─► [необов'язкове розбиття на тайли]
   ─► stem (space-to-depth + 3×3, крок 4) ─► backbone з Ghost-блоків (кроки 4/8/16 + контекст на кроці 32)
   ─► neck зверху вниз ─► голова на кроці 4: логіт «людина» + (l,t,r,b) для кожної комірки
   ─► вибір піків 3×3 + декодування рамок через softplus (numpy) ─► [x1,y1,x2,y2,score,class]
```

Детектор — щільна одностадійна безанкерна архітектура. Кожна комірка сітки з кроком 4 передбачає оцінку «центр людини» та відстані до чотирьох сторін рамки. Модель навчено з Quality Focal Loss (цільове значення оцінки — IoU) разом із функціями втрат для рамок GIoU і NWD, завдяки чому градієнти лишаються корисними для рамок завширшки кілька пікселів. Архітектуру написано з нуля на основі опублікованих ідей (CenterNet, FCOS, Generalized Focal Loss, GhostNet, NWD і SAHI; див. [NOTICE.uk.md](NOTICE.uk.md)). У int8-моделі дві фінальні згортки 1×1 голови залишено у fp32. Подробиці: [docs/uk/architecture.md](docs/uk/architecture.md).

## Навчання та відтворення

```bash
pip install -e ".[train]"                                       # додає PyTorch, pycocotools, tensorboard, pyyaml, safetensors
python scripts/prepare_data.py sources                          # звідки завантажити кожен набір даних і яка в нього ліцензія
python scripts/prepare_data.py hituav    --src ~/dl/HIT-UAV --out data
python scripts/prepare_data.py airesq    --src ~/dl/AIResQ  --out data
python scripts/prepare_data.py wisard-ir --src ~/dl/WiSARD  --out data
python scripts/train.py    --config configs/hae-s-ir.yaml --data data --out runs/hae-s-ir
python scripts/export.py   --checkpoint runs/hae-s-ir/last.pt --config configs/hae-s-ir.yaml --data data --out models-local/hae-s-ir
python scripts/evaluate.py --model models-local/hae-s-ir/hae-s-ir_lwir_int8.onnx --data data --sets hituav_test,airesq_val,wisard_ir_val
```

[`configs/hae-s-ir.yaml`](configs/hae-s-ir.yaml) — рецепт випущеної моделі, узятий з її контрольної точки навчання (порядок випадкової вибірки трохи відрізняється від оригінального запуску, тому повторне навчання відтворює модель статистично, а не біт у біт). Навчання тривало 42 хвилини на одній NVIDIA T4. Навчання на CPU працює, але повільно. Щоб донавчити модель під власну камеру, почніть із `models/hae-s-ir/hae-s-ir.safetensors`. Див. [docs/uk/training.md](docs/uk/training.md).

## Обмеження

- **Зсув домену — головний ризик.** AP50 становить 0,76 на HIT-UAV test, але лише 0,09 на WiSARD-IR (інші камери, локації та розміри цілей). Перш ніж покладатися на модель, перевірте її на своїй камері й висоті.
- **Дуже малих людей виявити важко.** На AIResQ (люди заввишки близько 8 пкс) повнота за збалансованого пресету становить 0,52 при приблизно трьох хибних тривогах на кадр.
- **Хибні тривоги.** Детектор спрацьовує на нагріте каміння, тварин, транспортні засоби та уламки. Перш ніж сповіщати оператора, підтверджуйте кандидатів у часі (трекінг, кілька прольотів).
- **Один запуск навчання, невеликі валідаційні набори.** Довірчі інтервали широкі.
- **Не оцінювалося:** щільні міські завали, великі натовпи, сильний дощ або туман, радіометричний 14/16-бітний вхід (спершу перетворіть його на 8-бітний), кольорові палітри, окрім white-hot у відтінках сірого.
- **Один клас.** Модель виявляє лише `person`. Вона не оцінює позу, травми чи те, чи жива людина, і не може визначити, хто це.
